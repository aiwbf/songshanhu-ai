# Web UX

## 目标

`apps/web/src/index.html` 是家长端咨询页，围绕两个入口组织：

- 快速问答：直接进入连续对话，适合问政策、流程、材料、转学等问题。
- 资格预判：8 步分步表单，适合先补充个案条件，再看结构化结果。

## 页面结构

左侧信息栏：

- 服务状态与官方联系方式
- 最近会话列表
- 新建会话入口

主工作区：

- 入口切换：`快速问答` / `资格预判`
- 快速问答面板：聊天时间线 + 输入框
- 资格预判面板：分步表单
- 结果面板：固定结构化输出

## 资格预判字段

分步表单覆盖以下主字段，并允许补充单位信息与产权归属：

1. 学段
2. 学童户籍
3. 监护人户籍
4. 工作地
5. 松山湖房产
6. 人才 / 优待身份
7. 单位信息
8. 是否转学

提交后统一走 `/chat`，因此资格预判和后续聊天共用一个会话上下文。

## 固定输出区块

结果面板固定展示：

- 初步判断
- 可申报类别
- 依据
- 材料清单
- 操作步骤
- 风险提醒
- 人工咨询方式

每条依据用 `<details>` 渲染，可展开查看出处摘要。

## 交互约定

- 资格预判完成后，可一键“转到聊天咨询”继续追问。
- 也可“继续补充资料”回到分步表单。
- 前台每次对话都会落到会话列表，并同步写入运营事件仓。

## API 对接

家长端直接使用：

- `GET /health`
- `GET /conversations`
- `GET /chat/{conversation_id}`
- `POST /chat`

返回中的以下字段直接映射到结果区块：

- `preliminary_judgement`
- `reportable_categories`
- `evidence`
- `materials_checklist`
- `operation_steps`
- `risk_notice`
- `human_consultation`

## 视觉原则

- 低饱和、安静、可信
- 不使用营销式大幅视觉刺激
- 家长端与后台共用同一套基础色板与组件，但家长端更偏咨询与阅读
