# 最危险的 20 个失败模式

以下 20 个失败模式按风险优先级整理，修复方向与 `evals/failure_modes/top20.json` 保持一致。

1. 误把 FAQ 当正式政策
修复方向：结论层必须强制引用官方 PDF / 政策文件，FAQ 只能做补充说明。

2. 误把历史文件当现行口径
修复方向：命中“最新/今年/现在/2025/2026”后直接进入时效保护逻辑。

3. 缺关键信息仍硬判类别或资格
修复方向：按 intent 维护最小必要字段集，缺关键字段时只允许 `need_info` 或 `handoff`。

4. 群聊泄露过多个人资料
修复方向：入站和出站统一做 PII 脱敏，群聊只保留必要摘要。

5. 该转人工未转
修复方向：把实时状态、概率、审核结果、人工裁量问题列为强制 handoff。

6. 渠道路由错乱导致串会话
修复方向：路由键必须包含 `channel + target + thread/sender/conversation`。

7. 时效风险漏报
修复方向：所有回答模板统一注入知识年份边界，latest intent 直接升级为 hard block。

8. 群聊未点名也触发回复
修复方向：默认开启 requireMention，未点名只允许静默或安全 no-op。

9. 未配对来源也允许发送
修复方向：高风险渠道默认要求 pairing，未配对只能 dry-run。

10. fallback 不安全直接放行
修复方向：fallback 只能 `safe_handoff` 或 `dry_run_only`，禁止 direct answer。

11. A/B/C 分类错误
修复方向：把类别判断做成结构化输出，并为 A1/A2/A3/B1/B2/B3/C 分别建回归样本。

12. 特殊项目映射错误
修复方向：为优才卡、优粤卡、港澳、台湾、华侨等建立显式 special program 规则表。

13. 房产锁定与解锁规则混淆
修复方向：拆分成独立 intent 与独立证据校验，不共用同一条回答模板。

14. 单位账号注册与审核流程混淆
修复方向：把开户注册、信息更新、单位审核、教育部门审核拆开建流程卡。

15. B1 名额问题被静态知识误答
修复方向：B1 名额查询统一归类为平台实时状态问题，默认转人工。

16. 误判 B3 与 C 不能同时申请
修复方向：对“能否同时申报”建专门规则和回归样本，不依赖泛化检索。

17. 非招生问题误入
修复方向：scope detector 使用领域负样本和低检索信号联合判定。

18. 引用来源错误或不匹配
修复方向：最终输出引用必须来自本轮最终 evidence 集，且校验 source tier。

19. 官方文件优先级倒挂
修复方向：检索排序和答案选择都必须优先官方 PDF，再到答疑和 FAQ。

20. 过时 FAQ 覆盖正式 PDF
修复方向：时间、截止日、年限字段做 cross-source consistency check，冲突时强制 handoff。
